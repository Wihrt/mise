# Monorepos — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (via `stacked-tdd-mr`) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** la chaîne (détection de la pile, couverture, mutation) traite chaque service d'un monorepo mise comme un dépôt simple.

**Architecture:** `config_roots` du `mise.toml` racine est la liste des services. Une commande Go `harness local stack` remplace le snippet bash de `repo-stack` ; la porte de couverture refuse un rapport qu'elle ne peut rattacher à aucun fichier suivi ; un fragment `monorepo.toml` agrège les tâches des services avec `//...:`.

**Tech Stack:** Go (harnais, tests `harness/acceptance` et unitaires), mise 2026.11.10, gremlins, pytest-gremlins, bats.

**Spec:** `claude/docs/specs/2026-11-27-monorepo-design.md` (ADR 0004).

## Global Constraints

- Un dossier par service ; `config_roots` est la seule source de la liste.
- Sortie de `harness local stack` : une ligne par dossier et par pile, `<dossier> stack=<pile> image=<yes|no>` ; `stack=none` sans `image=` ; `.` pour la racine.
- Erreur d'usage ou de configuration : code 2, message sur la sortie d'erreur.
- Règle des scripts : bash séquence, ne décide pas ; la détection est en Go, avec tests.
- Mutation : le code Go ajouté ou modifié est tué par un test unitaire de son paquet (`mise run mutation:go`, verdict `jq`).
- Repo-stack de ce dépôt : `stack=none` ; couverture sautée, comme les piles précédentes.

## Review Focus

1. `config_roots` avec une entrée absente, absolue, `..`, en double ou imbriquée → erreur code 2, jamais une ligne silencieuse (tâche 1).
2. `mise.toml` racine sous `.config/mise.toml` ou `.mise.toml` → lu comme `mise.toml` (tâche 1).
3. Rapport de couverture vide → même erreur qu'un rapport sans fichier suivi (tâche 2).
4. Rapport Go dont une partie des fichiers est générée et ignorée par git → la porte juge le reste, sans erreur (tâche 2).
5. Service Python dans un sous-dossier : `mutation:py` mute le fichier changé, pas zéro fichier (tâche 3).
